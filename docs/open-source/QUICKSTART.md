# 上手与配置说明

适用源码基线：`53982f104fb324662ad701ce54782b3cddd8e6dc`，2026-10-29。本文核对了源码脚本，未在本次材料准备中重新安装依赖、启动服务或调用真实模型。

## 1. 先看成果，无需安装

阅读[真实研究案例摘要](CASE_DIFY_CITATIONS.md)与[免密钥演示](DEMO_WALKTHROUGH.md)。前者来自已有导出，后者是明确标注的虚构演示，二者不能混作用户验证数据。

当前没有在本材料中提供可供所有人写入的公共在线研究空间。

## 2. 安装并运行离线检查

准备 Node.js 24 和 pnpm 11.25.0。进入本材料所在分支的 `source/`，保留锁文件：

```sh
node --version
pnpm --version
pnpm install --frozen-lockfile
node tests/run-local-api.mjs
pnpm exec tsc --noEmit
```

离线 API 检查使用模拟模型和测试存储，不要求真实模型密钥。通过离线检查不能证明真实研究质量或云端环境可用。

不要将 `pnpm dev` 当作标准 Next.js 启动命令：当前该脚本按执行配置选择 Vinext / Vite。原 Cloudflare 本地运行步骤见[历史配置文档](../../LOCAL_SETUP.md)，需要单独初始化本地 D1。

## 3. 当前 Next.js / Turso 路径

此路径需要你自己的 Turso 数据库。先在本机服务端环境或部署平台配置下表变量。数据库初始化脚本直接读取 `process.env`，不要只写入 `.env.local` 就假设该脚本会自动读取。

| 变量 | 应填写的内容 | 作用 |
| --- | --- | --- |
| `TURSO_DATABASE_URL` | 你创建的数据库连接地址，形如 `libsql://你的数据库.turso.io` | 指定数据保存位置 |
| `TURSO_AUTH_TOKEN` | 对应数据库的读写令牌本体 | 授权读写数据库；不是数据库地址 |
| `DASHSCOPE_API_KEY` | 你自己的模型服务密钥 | 真实模型请求需要 |
| `QWEN_FREE_TIER_ONLY_CONFIRMED` | 默认 `false`；仅在服务商保护实际生效后设为 `true` | 当前真实调用的保护确认；不是余额查询 |
| `JIANWEI_ACCESS_PASSWORD` | 自行生成的至少 24 字符密码，生产配置检查仍要求 | **当前 Node 路由没有用它拦截共享工作空间，不能依靠此变量提供访问保护** |

当前 `source/proxy.ts` 显式启用免密码共享工作空间。若远程部署，先通过部署平台的访问控制限制试用者，并使用独立测试数据库；在完成身份、数据隔离与调用额度限制之前，不直接向不受限访客开放写入和模型调用。

仅设置密码不会自动改变当前访问模式；本次材料没有修改鉴权代码。

配置完成后，在 `source/` 逐条运行：

```sh
pnpm run db:vercel:init
pnpm run build:vercel
pnpm run start:vercel
```

数据库初始化会访问你配置的数据库并创建缺失的项目表，不调用模型。已有项目数据不会自动从其他部署迁移。打开终端实际显示的本地地址。

### 模型兼容性

当前模型和接口地址固定在 `source/lib/research/provider-config.ts`，模型为 `qwen3.7-flash`。仅填入任意 API Key 不保证可用；先核对自己的账户、区域、接口权限和结构化输出兼容性。通用模型配置界面尚未实现。

真实研究会消耗你自己的模型额度。保护确认变量不能替代供应商侧的计费控制，也不能保证费用为零。

### Vercel 配置

项目根目录设为 `source`、Node 设为 24；当前 `source/vercel.json` 使用 `node scripts/vercel-release-check.mjs` 作为构建命令，输出目录为 `.next`。

该发布脚本包含离线检查、公开来源的联网检查和数据库配置检查；它不是免配置的普通构建。阅读[发布准备记录](RELEASE_READINESS.md)，不要沿用旧文档中的分支名称或把旧验收结果当作当前部署已通过。

## 4. 可选渠道

不需要一次配置全部渠道。未配置的渠道应被跳过，并在来源回执中说明原因。

| 能力 | 服务端变量 |
| --- | --- |
| Tavily 网页发现 | `TAVILY_API_KEY`、`WEB_SEARCH_ENABLED=true` |
| 博查网页发现 | `BOCHA_API_KEY`、`BOCHA_SEARCH_ENABLED=true` |
| GitHub Discussions | `GITHUB_DISCUSSIONS_TOKEN`、`GITHUB_DISCUSSIONS_ENABLED=true` |
| 允许列表社区 | `RESEARCH_COMMUNITIES` 选择 `n8n`、`discourse` 或 `cloudflare` 中一个 |

这些渠道共享来源请求预算。配置成功不等于获得正文，更不等于需求成立。各服务的费用、访问权限和配额需要自行核对。

## 5. 第一项真实研究

1. 使用独立研究项目，填写明确问题，先阅读界面实际预算。
2. 可先使用[案例的四条公开链接](CASE_DIFY_CITATIONS.md#可复用的输入)，每批最多 6 条；预览并核对再导入。不要把教程输出再次作为证据导入。
3. 先做单角色研究，检查原文是否支持关键结论；需要更多核查时再考虑多角色。
4. 查看未覆盖来源、失败、未知结果和用量回执，保留缺口。
5. 人工复核后，记录验证计划或导出草稿。没有访谈与付款数据时，保持未知。

## 常见卡点

- **数据库未配置**：分别核对连接地址和令牌，在实际运行环境设置；部署平台更新变量后需重新部署。
- **来源只有摘要**：摘要用于发现线索，不当作正文；补入有权使用的原始材料，或保留证据不足。
- **模型未就绪**：配置状态只检查设置，不能代替实际连接验收；先检查接口和权限，不重复提交未知结果的请求。
- **运行未完成**：查看执行保障和阶段状态，沿用原研究的预算与恢复入口，不通过新建重复请求掩盖失败。
