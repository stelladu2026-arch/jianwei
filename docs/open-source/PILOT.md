# 首批用户试用方案

目标：验证真实研究价值和首次使用门槛。当前是试用方案准备稿，没有已招募人数、使用数据或转化率。

## 首轮人群与规模

先找 10 位近期有明确软件产品决策的人，包括独立开发者和小型软件团队负责人。希望对方未来一个月确实要决定“做不做、先做什么、先验证什么”，而不只是随便体验 AI。

学习 Agent 架构的人可以另收反馈，但不混入研究产品的需求验证样本。10 人为探索规模，不代表统计验证。

## 发给试用者的邀请草稿

> 我做了一个早期产品机会研究工具“见微”，想邀请你带一个正在考虑的软件产品想法或功能问题来试用。它会整理资料来源、反对证据和下一步验证计划。首次可约 20–30 分钟，超时会记录原因；也可以先看案例再决定。你的真实材料是否公开由你决定，我只记录经你同意的脱敏反馈。最想知道的是：它是否比你原来的研究方式更省事，以及哪些结论你不信。

这是一段待使用的草稿，尚未发给任何人。不要承诺结果准确、零成本或必定在指定时间完成。

## 单次试用流程

1. 先记录对方当前问题、原来的研究方式及将要做的决定，避免只听产品介绍后的赞美。
2. 让对方先看案例，讲出自己认为工具会帮助完成什么。
3. 在独立部署或受控试用空间中创建真实项目。先不代操作，卡住时记录原因；必要时协助并标记。
4. 完成研究后，请对方指出一条有用的新证据、一条不可信判断，以及接下来准备采取的行动。
5. 征得同意后，在 7–14 天内人工回访是否采取行动、是否带来第二个问题；没有自动创建提醒。

如果研究未完成，也保留记录。模拟流程不计为真实研究完成。

## 访谈问题

- 最近一次要决定类似问题是什么时候？当时怎么查、花了多久？
- 这次哪条证据是你原来没发现的？能指出原文吗？
- 哪条判断你不接受？是来源、人群、推理还是现有方案有问题？
- 如果没有见微，这次你会用什么方法完成？
- 接下来会做什么？什么结果会让你改变决定？
- 下一个同类问题出现时，你会自己再次打开它吗？

不要用“是不是很好用”“你愿不愿意支持一下”代替行为证据。收费测试应在展示实际交付后另外提出，清楚说明内容与价格；口头兴趣不计为付款。

## 记录表

| 字段 | 填写方式 |
| --- | --- |
| 参与者 | U01 等匿名编号；联系方式单独保存并取得同意 |
| 角色与近期决策 | 是否符合首轮人群；问题和实际决定 |
| 开始 / 结束 / 主动操作时间 | 区分模型等待与人工操作；没有测量则填未知 |
| 完成情况 | 独立完成 / 协助完成 / 未完成 / 模拟体验 |
| 请求与费用 | 按实际回执、账单记录；未知不填零 |
| 有用证据与错误 | 对应来源与具体主张；避免仅记录满意度 |
| 决策或下一步变化 | 具体动作，记录是否实际发生 |
| 第二次使用 | 日期、新问题、是否主动；回访口头表示不计入 |
| 对外引用许可 | 是否同意公开脱敏评价或案例；默认不公开 |

## 首轮怎么判断

预先采用以下探索门槛，试验结束后不能为了好看改分母：

- 10 位符合条件的人中，至少 5 位独立完成一次真实研究；协助完成另列。
- 至少 3 位能指出具体新增证据或更清楚的下一步行动，不只给出“不错”的评价。
- 在约定观察期内，至少 2 位主动带第二个问题再次使用。

这些条件用于决定是否扩大试用，不证明产品与市场匹配。未达标先按“安装 / 操作 / 来源 / 判断质量 / 场景不频繁”归因。

如果做通用 AI 对照：使用相同问题和相同初始材料，记录模型、检索权限与用时；调整先后顺序，避免第二次已知道答案带来的优势。小样本先做逐案比较，不发布未经证明的提升百分比。
