# 研究与执行的业务流程

这是一份人工核对的解释图。是否仍与当前受监控源码一致，请先看[自动生成文档顶部状态](WORKFLOW.generated.md)和[指纹记录](manifest.generated.json)。待复核时，不把本页当成最新事实。

## 单角色研究

```mermaid
flowchart TD
  A["确认研究范围"] --> B{"使用当前已有原文？"}
  B -->|是| E["归纳机会与反证"]
  B -->|否| C["规划并采集资料"]
  C --> D{"有可分析原文？"}
  D -->|否| P["部分完成，保留证据缺口"]
  D -->|是| E
  E --> F{"允许补证且预算满足？"}
  F -->|是| G["判断证据缺口"]
  F -->|否| K["校验引用与结构"]
  G --> H{"有可检索的补证问题？"}
  H -->|否| K
  H -->|是| I["有界补充检索"]
  I --> J{"有新的可用正文？"}
  J -->|是| R["复核机会判断"]
  J -->|否| K
  R --> K
  K --> L["保存待人工确认的草稿"]
```

- “已有原文”模式从分析开始，不重新规划、采集或调用工具。单角色轮结束后仍可复用正文启动新分析；旧记录和用量保留。
- V2EX 专用模式从节点采样开始，不走关键词规划与自动补搜；上图合并展示了资料采集步骤，精确模式见[阶段序列](WORKFLOW.generated.md)。
- 采集预算耗尽会本地收尾；已有原文仍可用于分析，没有正文则部分完成。没有搜到不等于没有需求。
- 模型可请求受限工具，但预算和来源资格由应用执行；搜索摘要不能冒充原文。
- 项目与工具阶段共用标题、人群及排除项组成的研究范围，排除项不会被当作正向产品词。公开开发任务、原型交付或不匹配的产品仓库资料可能被规则筛出。导入材料仍需人工核对，规则命中不能替代语义相关性判断。
- 正文与摘要按资料用途类型区分；正文裁剪不改变其原文资格。开发任务提示与分析准入共用同一检测器；EPIC / Phase 实施清单和无使用经历的发票界面字段及引用副本暂缓纳入。有限词面检测仍可能漏判或误判。
- 已识别的外包／自由职业回款场景，反馈正文需同时匹配角色与业务动作；官方文档和背景资料仍按其用途保留，不能证明用户经历。泛化检索词会按明确业务场景映射为聚焦检索词，沿用原请求预算并记录映射；这不是通用语义相关性判断。
- 新生成的“已有替代”使用 quote-or-unknown/1：选择当前输入原文编号或未知，应用确定性附回原句与来源，不自由补写普遍现状。原句可定位仍不保证目标场景适用。旧格式与历史记录不改写。
- 发票、账单、访谈等主题可以检索；公开搜索不用于证明实际付款或私人账单事实，项目内已授权正文检索不受主题词拦截。
- 工具发布和销售帖按供给线索保留，不当作用户反馈或成交；机会问题在导出时标为待验证假设。工具循环按每次采集标记原查询、聚焦词与批次，不把合并回执假称为单次查询结果，不减少已实际发生的请求或重复数。
- 引用可定位只证明与输入资料有关，不保证语义支持或付费成立。

## 四角色复核

四角色复核已有冻结资料。独立反证不读取前序结论或解释性记忆；任务实际按待执行列表推进，不能把依赖图中的分支称为已经并行执行。角色依赖由代码生成，见[执行依赖图](EXECUTION.generated.md)。

需求、商业与反证的结果进入协调汇总，再做本地检查与草稿保存。多角色优于单角色尚需同输入、同口径的真实质量对照；四角色一致不能当作多个客户证据。

## 暂停、失败与恢复

```mermaid
flowchart TD
  A["读取项目版本、研究输入与预算"] --> B{"当前阶段可推进？"}
  B -->|是| C["预留请求并保存执行状态"]
  B -->|否| D["显示具体阻断原因"]
  C --> E["执行模型、工具或本地步骤"]
  E --> F{"结果和输入边界仍有效？"}
  F -->|是| G["保存回执、结果与检查点"]
  F -->|否| H["保留失败或未知状态"]
  H --> I{"满足阶段内恢复条件？"}
  I -->|是| J["复用原始线程与已确认结果"]
  I -->|否| D
  J --> A
```

- 模型 / 证据协议、来源配置和冻结输入变化时，不能盲目复用旧线程。
- 有未知操作回执时拒绝自动重发。暂停、取消或版本更新优先，迟到结果不能覆盖新状态。
- 已确认回执的输出截断，仅在当前输出上限高于失败用量、阶段及整轮有剩余额度时允许显式准备重试。准备不调用模型；继续推进时重新生成，不拼接或放行旧截断草稿。引用无效、超时及结果未知不开放这一恢复路径。
- 恢复不是重置预算；新增请求仍计入原轮剩余上限。显式重试、恢复旧检查点和阶段内恢复是不同操作。
- 后台任务以数据库租约和有界接力推进；中断后可能需要人工处理，不保证无限自动重启。

精确的拒绝原因、赋值表达式和源码行链接由[自动文档](README.md)提供。此图解释产品含义，不构成真实端到端验收报告。

### 无正文终态的检查点展示

`stopWithoutEvidence` 保持 partial / NO_USABLE_EVIDENCE，不继续调用模型。检查点标题和说明按该终态显示本轮结束；未运行阶段显示本轮未执行，没有当前步骤标记。采集收尾单独展示，不冒充完整采集阶段完成。终态页脚不再提示后台继续，原文/摘要/暂缓纳入数量分别展示；不会修改旧请求数或重新触发采集。

### 混合范围文字的产品排除

排除项字段可能包含“只研究 X，排除其他产品”等正向限定。产品排除仅对有限识别的负向/裸列举产品生效，不再把“仅/只研究 X”“非 X 产品”“X 以外的产品”中的 X 当作被排除对象；明确“排除 X”仍生效。原研究范围不改写，规则仍非通用语义解析。开发任务、界面副本及其他产品仓库的准入边界保持不变。新页面重算已有原文资格，不自动重启已结束轮次；可显式创建仅分析已有资料的新轮，沿用原文并保留历史用量。
