在线研究工作台 v0.6（四角色原文核查与人工对照），2026-10-04。基于《产品机会研究 Agent｜产品与架构设计》实现的首个可运行增量。

## 已实现

- 四角色复核已有真实资料：需求、替代与商业、独立反证、协调汇总，各一次 Qwen 请求，总上限 4；冻结同一输入，反证首轮不读取前序结论或记忆。每条主张给出模型支持度判断与原文连续片段，代码核对位置；角色分歧保留为待核查建议。
- 复用已保存的真实单角色基线，展示输入是否匹配、资源用量和两份主张；人工逐条对照与保存，无额外模型调用，不自动评出优劣。详见 [四角色核查与对照](docs/MULTI_AGENT_REVIEW.md)。

- 一键研究：确认方向 → 自动规划最多 2 个英文检索词 → HN 原帖及一级评论，加上中文维基百科条目正文 → 机会、替代与反证分析 → 判断可检索缺口 → 最多一轮补搜并复核 → 引用校验与草稿保存。最多 4 次模型请求，关闭补搜为 2 次；逐步持久化，可暂停、取消或恢复。这两种公开来源都不能代表国内用户。

- 项目总览、新建、编辑、归档、删除；服务端持久化。
- 明确研究简报并人工确认；范围修改递增 revision，旧机会全部待复核。
- 明确标识的 6 条虚构演示资料、2 个机会卡、4 个手动回放步骤。演示回放的真实模型调用为 0。
- Hacker News 关键词搜索，使用官方条目接口回源；同一次检索另读取最多 2 篇中文维基百科条目正文。每次最多 6 帖、每轮 6 次检索，失败保留已有资料。百科条目不是国内用户原话。
- 用户资料粘贴及 JSON/CSV/Markdown/TXT 导入，按同来源的完整正文去重；每批最多 30 条、文件 200 KB。
- 支持/反证/背景标记、排除、删除、引用原文定位、资料作者和讨论线程计数。
- 人工机会卡及验证计划；拒绝跨项目引用和排除资料引用；本版不能将付费信号标记为“强”。
- 报告快照（保留最近 10 版）、Markdown 与项目 JSON 导出。
- 乐观并发校验、最近 50 次变更调用幂等标识、迟到采集结果丢弃。

- 四角色能力白名单与只读上下文接口：校验项目版本、研究范围和证据归属；反证首轮不读取其他结论或解释性记忆。
- 项目级偏好、用户纠正、研究经验：来源、研究/资料版本、有效期；经验先候选，经人工记录验证后才可使用。可编辑、删除；编辑经验重新进入候选。
- 证据变更、机会变更、采集失败触发结构反思；人工反思保存问题、依据、可能原因、动作与验证结果。规则问题未修复不能关闭。

- 单角色基线与四角色固定依赖编排，统一模型契约和结构化输出校验；可选明确标识的模拟模式或 Qwen3.7-Plus；仅服务端读取密钥，保存真实用量回执。
- 服务端逐步执行、输入快照、步骤检查点、暂停/恢复/取消、过期检查点恢复、最多两次尝试和总调用上限。
- 原始资料优先级采样与任务上下文的 16,000 字符上限（不含固定系统提示及输出结构）；原文保持不变；范围、资料或记忆变化使执行失效。

## 在线架构调整

原设计 React + Python/FastAPI + LangGraph + SQLite 为可本地部署方案。当前在线平台运行在 Cloudflare Workers，使用 React/TypeScript（Vinext）+ 服务端 API + D1 SQLite。单角色模型步骤使用 LangGraph.js 的 web 构建；Python/FastAPI 没有接入。保留 `project_id / revision / call_id` 和模型角色接口。后续多角色对照继续以真实单 Agent 首测作为起点。

站点当前仅所有者私有，访问授权由平台负责。当前数据库为单用户工作空间；未来开放多人时必须先补用户归属和读写授权，不能仅放宽站点分享权限。

## 开发

保留项目自带包管理器与锁文件：

```sh
pnpm install
pnpm run db:generate # 仅修改 schema 时需要；现有迁移已生成
pnpm run build
```

本地数据库使用迁移，不在请求中建表。构建后可运行：

```sh
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_stormy_archangel.sql
pnpm start
```

已应用的迁移不要重复执行。托管开发环境使用 `sites-preview start <checkout>` 启动；其他环境依照原 starter 脚本配置。

`lib/research/model-port.ts` 是统一模型契约；`SimulationModel` 实现此契约并经过同一输出验证器。`QwenModel` 实现北京业务空间的 OpenAI 兼容 Chat 接口。密钥仅从服务端 `DASHSCOPE_API_KEY` 读取；免费保护未确认或密钥缺失时禁止真实请求。真实密钥不写入源码、前端、日志或项目导出。配置与首测见 [Qwen 接入](docs/QWEN_SETUP.md)。

实现边界见 [角色、记忆与反思](docs/GOVERNANCE.md)和[执行与评测](docs/EXECUTION_AND_EVALUATION.md)。

## 使用一键研究

1. 新建真实研究项目，填写方向、人群、地域、时间与决策目标并确认。
2. 打开“一键研究”，确认免费额度保护，选择是否允许一轮补搜，点击开始。
3. 保持页面打开，等待自动推进；关闭页面后可从检查点继续。失败不会自动重试。
4. 查看原始来源、模型输入输出、反证、证据缺口与草稿；人工核查后可保存机会卡。

见 [一键研究边界与恢复](docs/AUTOMATED_RESEARCH.md)。

## 体验模拟闭环

1. 加载虚构演示项目，在研究工作台确认范围。
2. 打开“执行与评测”，新建单角色或四角色模拟执行。
3. 连续推进或逐步推进，查看每步实际输入快照和结构化输出。
4. 选择一次格式错误或超时场景，观察失败后准备重试、再继续执行。
5. 运行 14 组固定流程评测，导出结果；模拟草稿与人工机会卡、正式报告分开保存。

验证：`node tests/run-local-api.mjs`，运行真实路由与内存 SQLite；无需模型密钥。
