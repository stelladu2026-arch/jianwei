# 分析输出截断修复（2026-10-29）

分析请求达到原输出上限时，提供方以 length 结束，应用拒绝不完整输出；这是输出长度问题，不是整轮请求次数耗尽。

将研究输出上限从 2400 调整为 4096，并在全部研究请求中约束单候选机会、简短叙述和有限缺口，保留引用、反证、未知及验证条件。失败区域直接展示已有错误名称，无需展开才能看见原因。

仍拒绝截断输出，不恢复历史草稿、不自动重试、不改变阶段及整轮预算。更高上限可能增加单次实际输出用量；不是保证不会再次截断。未调用真实模型。

验收：刷新独立预览，在原失败项目使用已有资料重新分析（新轮最多两次请求，旧轮计数保留），核查完整报告、引用与反证；此动作会调用真实模型，须由用户在页面主动发起。新项目可用「小型团队使用 GitHub Issues 整理重复反馈与排定需求优先级」，资料入口 github.com/microsoft/vscode/issues 与 github.com/microsoft/vscode-docs；入口只是检索方向，不是已核实需求证据。开启自动采集才能验证渠道，直接分析已有资料不验证渠道。
