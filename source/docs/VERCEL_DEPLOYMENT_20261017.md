# Vercel 迁移与验收（2026-10-17）

此分支准备标准 Next.js 部署，原 Vinext / Cloudflare 构建命令保留。迁移代码通过离线验收不代表云端部署或真实模型验收已经完成。

## 导入配置

- 部署迁移分支 `codex/vercel-deployment`，根目录设为 `source`。
- Framework Preset 选择 Next.js；Build Command 为 `pnpm run build:vercel`；Output Directory 为 `.next`。
- 使用 Node.js 24。保留锁文件，不在构建中初始化数据库或调用模型。
- 三个研究执行端点声明 `maxDuration = 300`；实际可用时长以部署账户和运行配置为准。原模型调用次数、已花费次数和幂等机制保持有效。

## 服务端环境变量

| 变量 | 配置要求 |
| --- | --- |
| `TURSO_DATABASE_URL` | 独立 Turso 数据库的 `libsql://…turso.io` 地址，或对应 HTTPS 根地址 |
| `TURSO_AUTH_TOKEN` | 该数据库的读写令牌 |
| `JIANWEI_ACCESS_PASSWORD` | 至少 24 字符的私有空间密码；浏览器登录用户名为 `owner` |
| `DASHSCOPE_API_KEY` | 所有者在部署平台私下配置的模型密钥 |
| `QWEN_FREE_TIER_ONLY_CONFIRMED` | 服务端设为 `true` 前，确认服务商“免费额度用完即停”已生效 |

这些变量均不得使用 `NEXT_PUBLIC_` 前缀，不得提交到 Git，不从原托管平台导出秘密。预览环境使用独立的数据库与访问密码，避免预览操作写入正式资料。可选语义检索变量默认关闭；只有单独完成配置后才启用 `SEMANTIC_RETRIEVAL_ENABLED` 和 `EMBEDDING_FREE_TIER_ONLY_CONFIRMED`。

Turso 资源和令牌需要另外配置；此分支不会自动开通或购买服务。未配置访问密码时所有页面/API 返回 503，未通过身份校验返回 401。密码正确但跨站的写请求返回 403。静态构建资源不包含服务端变量。

## 初始化与历史资料

在私下设置好数据库环境变量的 Node.js 24 环境中，从 `source` 执行 `pnpm run db:vercel:init`。脚本只创建缺失的 `research_projects` 表，不导入资料、不调用模型、不自动重试。初始化脚本依赖 Node.js 的 `registerHooks`，最低需 22.15，建议统一使用 24。

新数据库初始为空。原 D1 的项目和机会卡不会自动迁移。迁移历史资料需单独通过私有通道进行，保留版本、预算、已花费次数、记录和有效期；不要把进行中的执行重新启动为新请求。切换前保持原站点可访问，不将历史研究正文上传到公共仓库。
