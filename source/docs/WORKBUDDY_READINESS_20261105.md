# WorkBuddy上架差距与核查修复 · 2026-11-05

结论：目前适合先准备原生“产品机会研究专家”，尚不能把现有网页直接作为多人公用产品上架。Buddy应用是平台工作台配置与集成，不是任意Next.js项目ZIP的上传托管；第三方应用入口当前主要是硬件/积分及桌面分享接入，不等同于网页市场上架。原生专家与现有网页是不同运行环境，能力和用量不能混称。

## 已核对代码

- source/proxy.ts 的Node分支调用privateProxy(...,true)，按所有者既有选择免密码共享。private-proxy.ts只有源检查和私有缓存头，不生成用户身份。
- 项目表/存储和API使用项目ID读取，没有owner_id及租户授权；API公开市场使用前必须新增身份与每项目权限，不得依靠难猜ID或WorkBuddy安装身份自动隔离。
- Qwen和Turso及可选搜索配置依赖开发者环境；预算目前是项目级，不是市场用户级套餐。现有来源适配不代表WorkBuddy已具备同名工具。
- 单角色研究与可选复核可运行，但真实语义准确性未通过系统评测；分句核查也不能保证模型判断正确。

## 优先顺序

| 优先级 | 缺口 | 处理 |
| --- | --- | --- |
| P0 | 复合语句一部分有依据就可能整体获支持 | 本轮增加连续分句核查、完整原句上下文、每字段支持覆盖统计；分句非完整语义原子化，仍需模型及人工审查 |
| P0 | 模糊想法自主澄清尚未闭环 | 现网页先由人填写并确认范围；专家版需实现人群/场景/研究问题候选、最多三项关键追问与确认记录，不宣称当前已自动完成该第一步 |
| P0 | 发布路线与交付不一致 | 先原生专家独立适配；现网页继续所有者验收。明确不共享数据库、不复用开发者密钥 |
| P0（若接后台） | 登录、用户与项目隔离、每用户用量、可撤销授权 | 接MCP/网页后端前完成；WorkBuddy专家本身不自动提供该后端授权 |
| P0 | 实际工具可用性与语义基线 | 在WorkBuddy上实测零正文、无关引用、提示注入、版本条件、用户行业外推及失败恢复；记录平台/模型/输入/用量，不把离线回归当成准确率 |
| P1 | 平台安装包和说明 | 补插件配置、Agent定义、双语市场信息、头像、来源模板、使用步骤及示例；详见 integrations/workbuddy/README.md |
| P1 | 认证、收费与公开条款 | 完成适用主体认证及开发者信息；确认作者邮箱、许可、数据说明；如收费另完成变现入驻与签约，免费/付费属性选择前核对不可变更限制 |
| P2 | 实际使用反馈 | 记录有效启动、研究交付、引用可用、用户纠正、耗时/成本及复用；不预填用户数、收入或下载量 |

## 本轮分句核查

新单角色复核检查点按标点（括号内不拆）作保守句法拆分，每项保留完整原句、连续偏移及原字段引用；不重写原句，不将子句当独立事实。最多12项，每项最多一段引文及80字符说明，保持有界输出；超限在请求前停止，不截断。四角色契约保持原样。

已有单角色零请求ready检查点可显式“拆分待核查主张（不调用模型）”。不重置id、预算或报告；已发出请求、存在lease、有结果或非ready时拒绝拆分，旧格式照旧读取。每个分句均必须覆盖，模型不能漏项。字段只有全部子项被判支持时才显示全部支持，仍标明模型判断待人工核查。

这不是确定性的事实裁判，也没有实现完整语义命题抽取。一个分句仍可能有多个并列事实；用户行业、适用条件和因果需要结合完整原句核查。本轮未自动改写原草稿或执行真实模型。

## 验收输入

继续原n8n项目/26条正文，零请求旧检查点先点拆分。问题描述应拆开人群/场景、故障、恢复和监控等分句；完整原句可展开，引用不能从别的字段借用。只拆分不调用模型。已有执行记录不重置；真实执行单独授权。

新增合成对照项目（非市场证据）：标题“培训机构课后作业收集与反馈”；范围“仅验证研究结论支持关系”；给三份明确标注虚构的资料：A老师自述每周手工整理两次作业、B现有平台已支持批量收作业、C仍未取得家长或学生反馈。检查是否将A外推为全行业刚需、忽略B或伪造C人群痛点。真实市场研究应重新检索/导入获授权原文，不能把此样例当商业证明。
