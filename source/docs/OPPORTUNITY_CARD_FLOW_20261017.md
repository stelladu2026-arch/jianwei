# 机会卡保存、复核与删除 — 2026-10-17

保存研究结论时，复用同一 analysisRun 对应的自动草稿或已确认卡片；再次打开保留人工修改。服务端按本项目的研究运行关联更新卡片，并对完全相同的人工新增判断去重。不同假设仍可共存。当前不自动合并或删除历史重复卡，以免丢失人工修改。

保存成功后进入机会判断，定位对应卡片，并显示成功反馈与下一步：复核、补计划、查看本卡计划或保留暂缓依据。查看计划会定位到这张卡的计划，并返回当前报告草稿。计划仍需用户实际执行与另行导入证据，不自动认定市场需求、付款或研究完成。

卡片列表显示编辑、删除按钮。删除先确认，只删当前卡，原文和历史报告快照保留。失败时确认框保持打开并显示原因，版本冲突刷新后可显式重试。保留已有 CAS 和 callId 幂等；防止同帧重复操作。旧编辑窗口不能以已删除的编号复活卡片。已删来源运行不会在自动草稿保存时重新出现，用户仍可显式从研究结论重新复核保存。

新增 17 项离线回归：真实 SQLite 路由的保存、来源关联、防重复、CAS、删除、冲突后重试、删除后防复活、显式重建，以及 React 静态展示和按钮分支。完整离线套件 425 项通过，类型检查通过。生产构建与发布以发布工具结果为准。

验证边界：未调用真实模型；未执行访谈、实验或付款验证。当前环境没有可用浏览器控制，弹窗焦点、滚动和移动端的实际点击仍待网页验收。

D1 存储故障：底层异常转为可理解的提示，保留有界排查编号，不展示原始数据库内部错误。写入异常不等于没有提交；提示先刷新确认，再显式重试。故障注入覆盖写入前失败、提交后响应丢失、删除已提交后报错、列表读取失败，以及旧接口原始 D1 错误的浏览器兼容。读取失败不呈现为空项目，数据库故障不触发自动写入重试。线上读取正常只能说明读链路可用，不能据此认定先前操作成功。
