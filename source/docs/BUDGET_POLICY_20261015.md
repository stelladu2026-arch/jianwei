# 阶段请求预留与用量说明

## 问题与行为

一个研究阶段可能包含多次模型请求：模型提出工具需求，应用执行工具，再调用模型读取回执。此前规划阶段可以占满整轮请求次数；页面又把阶段汇总用量当作一次回执，容易把“应用请求次数上限”和“提供方账户免费额度”混淆。

新创建的流程标记 opportunity-workflow/4：

- 规划及补证规划至少为后续分析保留一次模型请求；应用仍保留原轮总上限，不增加费用权限。
- 当前阶段最后一次调用关闭工具，发送明确的最终输出要求，并以提供方 Schema 限制 tool_calls 为空。模型违约仍严格拒绝，不执行额外工具或接受临时答案。
- 规划失败后的手动重试不能占用为后续分析保留的最后一次请求。界面与服务端共用同一检查。
- 用量按每次模型回执统计；阶段聚合仅用于摘要，不能再次累加。每阶段展示调用尝试与回执数量，缺失回执按未知记录。
- 停止原因分别说明整轮请求上限、当前阶段分配上限和提供方免费额度耗尽。历史计数、失败结果及旧报告快照不回写。

本轮次数限制不等于余额、词元额度或实际账单。模型和工具仍需原有权限、输入版本、租约、引用检查和免费额度保护。无法完成时保留可交付原文与阶段成果，不补写结论或自动追加调用。

## 离线检查

新增 12 项故障与显示回归：实际 SQLite 路由配合虚构提供方接口，覆盖连续工具规划、最终阶段输出、分析请求预留、两次总上限、最后一次输出违约、失败计费保留、幂等、历史展示、回执缺失与 React 渲染。连同既有检查共 368 项通过，类型检查通过。

这些检查不代表真实模型工具循环或市场语义质量已经验收；浏览器点击、实际渠道可达性和真实模型输出仍需分别验证。本文件不包含真实运行项目标识、用量回执或私有部署信息。
