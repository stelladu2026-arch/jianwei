## 已实现

- 安装并锁定 Deep Agents 1.14.0 及兼容的 LangChain 依赖，保留项目的依赖发布时间保护。
- 新建研究使用 SDK 执行单角色工具循环和四角色模型步骤；旧研究继续使用原执行器。
- 使用模型桥接器将现有 Qwen 严格 JSON 协议转换成 SDK 的标准模型和工具消息。现有模型适配器、引用校验、角色冻结输入和业务预算继续生效。
- 在现有 SQL 数据库边界上实现检查点保存器，不使用 Vercel 临时磁盘，也不引入第二个数据库。
- 单独保存外部操作日志。完成的操作可以复用；已发出但结果未知的操作会阻止自动重发。日志采用数据库唯一约束防止并发重复执行。
- 工具批次串行执行，避免多个工具同时检查并消耗共享预算。模型和工具执行前验证当前项目版本与执行租约。
- 将限定证据、研究简报和可用记忆放入 SDK 虚拟工作区；反证角色不读取其他角色记忆。正文只作为数据处理。
- 新增执行保障状态接口和界面，只返回本项目本轮执行的检查点及操作数量，不暴露原始检查点正文，也不接受客户端指定任意线程。

## 当前刻意保留的约束

- SDK 自动摘要、自由派发子 Agent、Shell 和通用文件写入暂未开启，避免超出原有每轮 2/4 次模型请求和 ¥0 付费预算。
- 四角色仍由现有业务编排控制，独立反证先看原始证据，协调角色最后汇总。
- 当前上下文仍采用确定性裁剪和项目内检索。没有把这些能力描述为已实现自动语义压缩或自动学习。
- 恢复 SDK 线程的核心接口支持 `resume:true`，输入和原始预算必须完全匹配。面向用户的阶段内恢复操作及后台调度尚未接入；原有页面恢复仍按业务阶段运行。

## 主要文件

- `lib/research/harness/runner.ts`：SDK 执行器和 Qwen 协议桥接。
- `lib/research/harness/checkpointer.ts`：SQL 检查点和待提交写入。
- `lib/research/harness/storage.ts`：数据库结构、线程绑定和外部操作日志。
- `lib/research/harness/workspace.ts`：限定证据和角色记忆的虚拟工作区。
- `lib/research/harness/status.ts` 与 `/api/projects/[id]/harness`：执行保障计数。
- `tests/harness-smoke.mjs`：预算、越权、并发、恢复及结果未知故障测试。
