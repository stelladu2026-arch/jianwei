# P1-P2 渠道分配与启动交互（2026-10-29）

## 实现
- 移除“开始前还需完成X项”独立检查卡。原有启动校验、原因和可操作入口留在启动按钮旁，加载/忙碌时不显示无法操作的按钮，全部就绪时保持安静。恢复四角色的阻断提示沿用紧凑样式。
- 来源按程序规则分为已有能力、用户反馈、背景统计与通用发现目标；根据目标调整候选渠道顺序。产品题目在预算允许时同时保留至少一个官方能力检查和一个使用反馈来源。每词10次上限不变。
- 初始分配后，以原文资格检查是否缺少目标类型的资料；仅未用请求额度可转给一个从未执行的同目的渠道。不是模型语义缺口判断，不更换关键词、不重试失败渠道。没有合适候选时保留缺口，不强行花完额度。保留原文回源额度。
- routing保存目标、每渠道分配额度和余量转配标记；界面区分配额和实际请求，并分别说明未配置、预算、主题和语言跳过原因。
- n8n官方资料与最近5条发布记录已接入固定读取；时区/定时查询选择Schedule Trigger常见问题文档，其他n8n查询读执行记录说明。文档日期未知明确说明；固定文档并非全库检索、最近版本不是完整修复历史。参考：https://github.com/n8n-io/n8n-docs/blob/main/docs/integrations/builtin/core-nodes/n8n-nodes-base.scheduletrigger/common-issues.md 。
- 单多角色对照基线保存已知请求次数，旧快照未保存时显示未知；不会自动生成新基线或执行真实对照。人工评审提示关注原文支持、人群场景、反证、计划与投入收益，不用条数替代研究质量。
