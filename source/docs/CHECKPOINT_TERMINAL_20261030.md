# 原文不足终态展示修复 · 2026-10-30

用户反馈同一检查点同时显示“等待继续”和“本轮已结束”。后端 stopWithoutEvidence 已正确设置 partial / NO_USABLE_EVIDENCE，不会继续分析。前端 ResearchActivity 缺少 partial 标题分支，页脚仍使用通用后台推进说明，造成冲突。

本轮修改：
- partial 明确显示本轮结束与原文不足；completed、partial、cancelled 不再标当前待执行步骤。
- 未执行阶段标为本轮未执行；采集收尾单独标记，不计为完整完成阶段。
- 终态忽略尚未清理的浏览器 pending 标记，防止迟到的本地等待状态覆盖已保存终态。
- 终态页脚不再提示后台继续；原文不足时分别显示当前可分析正文、摘要与暂缓纳入正文数量。
- 不修改采集规则、模型、预算或后端转移，也不重跑历史研究。正文不足是本轮采集结果，不是“没有需求”的结论；仅凭用户贴出的文字不能确定具体渠道为何未取得合格正文。

验证使用完整离线 API 套件、React 静态渲染与类型/构建检查。新增终态和迟到 pending 回归。真实模型调用为 0；页面真实采集结果仍需用户验收。

## 新验收项目与资料

项目：小型开源社区的 Discourse 邮件通知与主题跟进。
人群：维护自托管 Discourse 的 2–5 人社区运营团队。
场景：用户反馈邮件通知未收到或主题跟进遗漏，运营需核查设置与投递记录。
目标：判断已有通知配置能否解决，还是值得做轻量排查助手。
范围：近一年中英文；仅 Discourse，排除开发路线图、纯界面实现及其他社区产品。
资料入口：https://github.com/discourse/discourse/issues 和 https://meta.discourse.org/ 。仅作为候选入口，未核实为本轮需求证据；不要整页导入。
使用自动采集、关闭补搜。若原文不足：标题应显示本轮已结束，无当前步骤、等待继续或后台继续提示，已用请求不归零；可补充原文后显式开始新轮。若取得正文：仍按原流程继续，不因本次界面修复提前结束。
