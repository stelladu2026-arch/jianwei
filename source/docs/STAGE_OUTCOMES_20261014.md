# 2026-10-14：停止后的成果交付及同类场景排查

## 用户问题与结果

用户指出：失败后只显示“已停止”，无法交付完整结论，已有研究投入也难以使用。本次改为在停止、暂停、取消、等待继续或输入过期时，自动整理“本轮已有成果”：已有原文、已接受的阶段分析、缺口、未完成步骤及下一步。原研究流程与预算不被改写；报告只由本地规则生成，不新增模型请求。

第一阶段失败时，交付已有资料，明确尚无机会结论。需求/商业阶段通过而后续失败时，交付已有分析，明确反证或协调尚未完成。模型分析通过但本地检查/保存尚未完成时，只展示候选草稿。第二轮复核失败时，保留原完整草稿和机会卡，单独标记第二轮未完成。没有原文或有效分析时诚实说明暂无成果，不虚构结论。

## 排查与修复

| 场景漏洞 | 调整 |
|---|---|
| 失败、暂停、取消或等待继续只展示流程状态或原始 JSON | 自动提供可阅读、可导出的阶段成果报告；一键研究、独立执行、报告与验证及历史记录均可查看 |
| 工具采集正文有效，但随后模型失败使正文不保存 | 在同一有效 lease/CAS 边界内独立保存符合采集规则的正文；不保存失败模型结果、标题桩或失效/迟到资料 |
| 分析中新增工具原文，资料版本改变，使后续本地检查被旧版本阻断 | 仅在本轮未被编辑的有效 lease 内，把成功单角色分析绑定到已保存的工具原文版本；不更新旧基线/历史/失败结果 |
| ready 检查点预算耗尽，继续按钮仍能发起必失败操作 | 共享服务端/界面推进预算检查；模型与采集预算不足时明确停止理由，并可导出已有成果。本地检查/保存不因模型次数耗尽而被禁用 |
| 独立执行页未预先阻止正在进行的结论复核 | 界面与既有服务端限制一致，明确指引先完成或结束复核 |
| 研究或复核仍在进行，却能确认项目交付完成 | 界面和服务端拒绝提前完成；先处理检查点，阶段成果仍可导出 |
| 保存报告快照会增加版本并意外打断进行中的请求 | 有 lease 时提示先导出，步骤结束/过期恢复后再保存快照。导出是只读，不改变版本 |
| 输入已删除/排除/变化时，旧分析被误当当前结论，原文难以追溯 | 用对应模型输入快照展示原文；明确历史范围和资料版本，不拿新原文替换旧引用。不具备旧快照时不借用当前范围资料 |
| 证据不足和执行失败混淆；模拟结果像真实研究 | 完成流程但保留证据缺口时说明仍待验证；模拟报告单独标记。没有检到资料或调用失败不等于没有需求 |
| 旧保存结果存在错误引用、角色越权或缺少输入 | 重新应用现有结构、原文和角色边界检查；不可交付内容计为 withheld，不修补，不混进报告 |

## 报告及数据边界

- 只使用 done 的记录/任务中可按保存输入重新校验的结果；failed/running/pending 中夹带的输出不进入分析。
- 输入原文可以独立交付，包括失败步骤的输入快照，但不读取其前序摘要作为新分析。实质支持程度仍待人工核查。
- 保留原始主张、引用、已定位片段、候选问题/判断、反证、未知项及未执行验证计划；规划检索词不是机会结论。
- 同编号不同文本/裁剪片段按输入分别保留。原文版本数不是独立客户数。
- 公开言论、自述和多角色一致不能作为已核实交易；fact 仍须逐字原文，且不是独立核实市场事实。
- 当输入或记忆变更、旧结论待复核时，成果用于追溯，不能当成当前结论。
- 不自动创建正式机会卡、正式完成状态、已确认记忆或 resolved 反思，不增加重试，不改变已花费预算。
- 当前报告导出及显式保存的新报告快照包含阶段成果；旧快照保留原样。项目 JSON 保留原执行记录，阶段报告可从记录重新生成，无数据库迁移。
- 仍保留现有项目 600,000 字符容量与有限历史保留限制；大量正文/快照达到容量上限时，先导出并整理或新建项目。本次没有建立无限审计仓库。
