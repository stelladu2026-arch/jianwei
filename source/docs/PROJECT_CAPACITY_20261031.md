# 整项目保存容量修复 · 2026-10-31

用户报告“项目资料已达到本版容量，请导出后新建项目”。该文案的唯一触发点是store.save对整份JSON的600000字符检查；不是正文条数或模型额度。正文、执行输入快照、冻结输入、报告与历史共同占用空间。本轮未读取线上项目，尚不能报告其实际大小或各部分占比。

改为新建与保存统一的2,000,000 UTF-8字节上限，保留有界容量。不会自动删除、截断、清空或改写旧记录，不扩展模型上下文或请求预算。容量失败和CAS冲突不再先行修改调用对象版本与时间。达到新上限时保留明确错误，不允许无限增长；更大的长期项目仍需后续做独立历史存储。

## 验收

继续原n8n项目及26条正文，在新验收版刷新项目后，重做刚才被拒绝的“创建结论复核检查点”。只创建、不点击执行，应零模型请求，并列出三项待核查主张。已有资料、草稿、预算应保持。若旧提示发生在其他保存动作，则重做该动作。未保存的修改不会被自动恢复，不自动重发研究请求。

离线检查覆盖：超过旧60万字符项目仍可写读；中文UTF-8超限不写入，调用对象版本和时间不变；CAS冲突不改元数据；新建与更新使用同一字节边界。真实项目及真实模型尚待用户验收。

实际结果：完整离线API在SQLite及Turso兼容模拟HTTP边界各通过，含大项目零请求创建/取消复核检查点；TypeScript与Next生产构建通过；12项逻辑文档检查通过。Archify首次浏览器运行因本地二进制截断失败，修复运行文件后四项自动门全部通过，未做人工图像检查。原项目真实大小和线上保存仍待验收，本轮真实模型调用0。
