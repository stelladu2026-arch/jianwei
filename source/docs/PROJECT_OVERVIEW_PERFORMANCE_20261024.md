# 项目总览按需加载（2026-10-24）

## 问题与实现

总览此前读取最多 100 个项目的完整 payload，SQL-over-HTTP、API 响应与浏览器都承载原文、模型上下文、阶段历史和报告。总览只需要标题、状态和计数，却需等待全部详情。

新增 GET /api/projects?view=summary：数据库只投影目录字段、当前检查点元数据和实际计数。原文、历史报告、模型输入输出均不从 SQL HTTP 连接返回。默认列表响应保留兼容性；GET /api/projects/[id] 按需读取单个完整项目。两者都沿用既有私有访问保护和 private, no-store 策略。

前端目录与详情分开存储。在总览展示摘要；进入项目才读取详情，同一页面会话内相同或较新版本可复用。返回总览只刷新目录。切换项目、返回总览或组件卸载取消尚未完成的详情读取；显式版本合并及当前选中项检查防止旧响应覆盖新修改或恢复已删除项目。详情读取失败有明确重试入口，不伪装成空项目。

没有将原文写入浏览器持久存储，没有跨用户公共缓存，没有新增模型调用或后台自动重试。

## 验证

新增七组检查，经过真实内存 SQLite 和模拟 Turso SQL-over-HTTP 协议：目录两层传输不含重型字段、完整详情和旧列表兼容、各检查点及租约状态一致、React 目录与计数显示一致、并发版本合并/删除边界、更新与归档计数、取消读取且不自动重发。

合成大型项目中摘要 API 小于完整 JSON 的 1%，SQL HTTP 响应也少于 3 KB；这是离线字节量验证，不能写成线上延迟或百分位性能指标。实际加载还受到部署冷启动和数据库网络延迟影响。

完整离线回归 599 项 PASS，收到 RESEARCH_API_SUITE_COMPLETE；TypeScript 和 Next 生产构建通过。真实网页的加载耗时及详情切换仍待受支持的私有访问入口验收。

## 后续产品验收

用户已确认协调汇总完成。下一步先确认引用校验与草稿保存也结束，再创建结论复核检查点并执行一次结论复核；核查不改写原研究。随后人工确认机会草稿、重复保存检查、保存报告快照及明确确认本次研究完成。删除仅验证指定可丢弃卡片，保留研究原文和报告；现有真实记录不为验收自动删除。

本次代码修复和发布不发起真实模型请求。结论复核沿用每阶段最多两次的预算和显式操作，不能把用户确认的协调完成扩大描述为全部网页验收完成。
