# 采集次数用完后的本地收尾

模型在规划阶段调用检索工具，会与后续固定采集共用来源、检索次数限制。此前即使已经取得可分析正文，固定采集仍可能因为下一次预留不足停在 collect，无法转入分析。

opportunity-workflow/5 对 ready 且无活动租约的 collect/supplement 增加本地收尾：

- 达到本轮检索次数、项目累计次数或来源请求预留上限后，不追加外部请求。记录剩余未执行检索词和收尾原因，不将未执行查询记为成功采集。
- 首轮采集已有可分析正文则进入分析；无可用正文则保存部分成果，不生成机会判断。已排除、虚构、只有标题、过短及不在本轮范围内的公开资料不能触发分析；合格的导入正文可沿用。
- 补搜没有新增原文时保留已有分析，进入本地校验；缺口工具取得新正文时仍要求重新分析。缺少已接受分析的异常补搜状态不会被自动跳过。
- 新流程在每次正常阶段结束后自动检查；旧 ready 检查点可点击“结束采集并保留已有资料”，该操作本身不调用模型或来源，也不需要额外免费保护确认。后续模型分析仍需要原有配置、确认和请求预算。
- 不对 failed/running/paused 或带租约的步骤自动收尾，不清除原失败、原用量，不追加重试。版本冲突、暂停、归档及输入版本边界保留。

界面和阶段导出分别显示“采集已收尾，部分检索未执行”；原文、已接受分析和不完整覆盖的限制均保留。本地收尾完成不表示所有检索都执行过，也不表示形成市场结论。

验证：新增 13 项实际 SQLite 路由及 React 静态回归，共 400 项离线检查通过；TypeScript 和托管生产构建通过。覆盖三种上限、幂等、版本冲突、项目状态、无正文、合格原文过滤、最后一次采集自动收尾、补搜保留与重新分析，以及展示标识。外部模型和来源均使用虚构 HTTP。浏览器及真实新版完整研究另行验收，离线通过不等于真实语义质量或完整流程通过。
