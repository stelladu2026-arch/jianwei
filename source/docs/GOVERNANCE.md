# 角色、记忆与反思实现

当前已实现治理基础、固定编排与 Qwen 适配器。单角色研究流程会执行模型请求的白名单工具：Hacker News 检索/阅读、中文维基百科摘录，以及当前项目资料的词面检索。上下文端点仍只返回限定资料，不执行这些工具。真实模型对这套工具 Schema 的接受情况尚未验证。

## 权限边界

`POST /api/projects/{id}/context` 必须匹配最新 project version 与研究 revision，范围已确认，指定证据必须属于当前项目且未排除。工具能力不在角色白名单则拒绝。反证首轮只读取简报、原始证据和应用预算，不读取机会卡或记忆。其他角色只读取选中资料及引用落在该资料集内的可用记忆/机会卡；需求角色不读机会结论。

当前用户通过已有项目 PATCH 管理记忆与反思。此用户管理接口不是 Agent 工具，模型适配器不得将任意 HTTP 或此 PATCH 暴露为工具。模拟模型执行已加入运行 ID、预算预约、调用幂等、输出参数验证、取消后的迟到结果隔离和有界重试。单角色工具循环只执行上面的四个白名单工具，不能绕过能力白名单去访问数据库或任意网址。

站点保持所有者私有；权限白名单是角色能力隔离，不替代用户身份授权。多人使用前须新增资源归属验证。

## 记忆

工作记忆继续使用研究状态、暂停进度与预算；项目档案使用原始证据、范围版本、变更记录及报告快照。

显式记忆仅保存本项目偏好、用户纠正和研究经验，每条携带用户来源、引用、创建时间、范围与资料版本、有效期和验证记录。经验创建和编辑均为 candidate；confirmed 需要用户另行提交非空验证记录。候选、过期、范围变更、引用失效、资料变更的解释性记忆不进入角色上下文。偏好不依赖资料版本，但仍受范围版本和引用可用性约束。

纠正和经验必须引用当前可用资料；这是来源可追踪规则，不表示引用在语义上支持内容。编辑重新建立当前范围与资料依据，原始创建时间保留，已有验证清空。数量上限 100 条。未实现跨项目全局偏好、向量检索或自动经验晋升。

## 反思

资料或机会变更自动检查待复核结论、删除/排除引用、缺少原始引用与缺失验证计划；采集失败记录“未完整完成”。同范围、资料版本下相同开放问题去重；达到 100 条后自动检查停止新增记录，核心数据修改不因此阻塞。用户可以删除不需要的记录。

规则反思是确定性结构检查，没有判断语义、分析偏差原因或证明市场机会。人工反思的原因始终作为待验证假设。规则检查项必须从当前项目消失，且提交非空验证记录，才可标记 resolved；用户反思需要提交验证记录，不会被当作自动验证事实。

本版本不会自动修改系统提示词、预算、研究范围或模型选择；没有 Agent 互聊循环。当前执行提供模拟/Qwen 单角色基线与反证独立首轮，已控制总调用预算及取消边界。单角色工具循环的跟进调用只发生在剩余模型额度内，不是失败后的隐式重试。真实模型语义质量验证及阅读结论后的反证第二轮、按缺口最多两轮补证仍待实现。跨项目经验复用要在有可重复评测后开放。

## 存储与兼容

新增字段为项目 JSON 中的 memories/reflections/evidenceVersion，旧项目缺失时使用空集合和资料版本 0，无数据库结构迁移。沿用项目 CAS 与调用幂等。JSON 导出包含记忆和反思；旧报告快照保持不变。

研究执行期间新增、编辑、确认或删除项目记忆，会使当前执行标记 stale；已有输入快照保留，不混用旧任务与新记忆。
