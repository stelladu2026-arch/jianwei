## 线上联调与发布

沿用现有 Vercel `stella-s-projects88 / jianwei` 项目及其服务端配置，不导出密钥、不将 `.env` 加入仓库。当前连接器返回团队范围 403；部署 CLI 尚无凭据，需账号所有者完成一次设备授权。代码已具备可提交及构建条件，这属于发布权限阻塞。

`node scripts/verify-harness-live.mjs` 默认拒绝调用。显式执行需 `--live --max-model-calls=2 --paid-budget=0 --run-id=<UUID> --ref=<40 位提交 SHA>`，并要求现有服务端免费保护配置有效。该脚本使用独立虚构工程资料，验证真实 Qwen 工具循环、Turso 中已确认结果后的检查点故障恢复、完成回放零请求，并删除该虚构线程。它不写入真实项目或市场证据。

验收授权写入 `research_harness_acceptance_runs`，请求前原子预留，总上限两次；同一 ID 和版本完成后只复用安全结果，未完成则停止，不因构建重启重新分配额度；改变版本必须拒绝。同一编号不允许自动换新或重试失败请求。完成后保留少量授权回执用于防重放。¥0 是付费预算约束，不是已经核实的实际账单。

仅在一次经授权的生产构建中传递以下非敏感 build env：

- `JIANWEI_HARNESS_LIVE_ACCEPTANCE=1`
- `JIANWEI_HARNESS_ACCEPTANCE_ID=<本轮唯一 UUID>`
- `JIANWEI_HARNESS_ACCEPTANCE_REF=<本次提交 SHA>`

正常构建不设置这些标志，不调用模型。发布检查先执行离线门禁、有限公开来源探测、生产数据库结构检查和 Next 构建，再执行线上验收。任一强制门禁失败则构建失败，不替换既有正式版；公开渠道可用性探测仅报告结果。失败后保留本轮 ID 和回执，检查安全错误字段，不自动追加真实调用。

成功后仍需核对部署 READY、私有认证、恢复操作、后台状态与页面刷新行为，记录实际用量与回执；本轮两次请求工程验收不能替代完整真实研究或四角色语义质量验收。后续再按明确请求预算安排这些场景。
