# 角色输出格式与原文选择

本说明描述代码行为与离线检查，不包含真实项目编号、运行用量、请求回执或私有部署信息。

## 新格式

当前生成格式 claim-selections/2，角色协议 evidence-review/7，提供方 Schema 名称 review_v8_*。

- 资料事实只填写 kind=fact 与 quote_id；应用按本次固定原文目录生成原句及定位证明。定位证明与模型支持判断分别展示，不能视为来源、市场或交易已经核实。
- 假设、未知、反例各自内嵌 check；机会问题和机会结论各自携带核查对象。应用按主张位置生成内部 target。
- 引用选择目录中的 Q 编号，展开同一编号对应的原文与资料标识。未知编号、重复编号、角色越权、非 insufficient 无依据及引用越界仍拒绝。
- 核查说明使用受控 reason_code，按 judgment 限定可用枚举，映射为有界中文说明；具体分析、反例和未知保留在正文。新格式禁止自由 reason 文本，不通过截断接受旧超长输出。
- claim-anchors/1、claim-selections/1 等旧格式保留严格解码。新格式只在明确版本下展开，不修补旧失败或替换冲突引用。
- 内部结果仍经统一结构、目标覆盖、引用归属与逐字原文定位检查。首轮独立反证不读前序结果或记忆；协调读取三个角色的有界摘要。

## 提供方兼容

依据官方文档检查发送 Schema，避免 uniqueItems、contains 等服务不支持的关键字；去重、目标覆盖等约束由运行时严格执行。发送前兼容检查防止已知不支持的格式进入模型接口。错误诊断只保留固定状态与关键字，不记录提供方私密正文。

官方参考：https://www.alibabacloud.com/help/zh/model-studio/qwen-structured-output
