# 2026-10-15：真实四角色验收与引用生成契约

## 实际失败与改动

沿用已完成真实单角色研究的同一项目、范围、6 条固定原文和有效记忆，复用单角色基线。首轮需求角色请求后被拒，字段 `data.checks.1:invalid_selected_fact_check`；原文、原基线、已花费一次请求及安全回执保留。被拒正文未保存，不能反推其具体判断值或多余字段。

旧生成格式把 fact 笔记和对应检查独立选择，存在生成时自由组合、解码时要求二者严格配对的风险。新格式为明确版本 `claim-selections/2`：

- 资料事实仅填写 kind=fact/quote_id；应用按同一固定原文目录生成原句与定位证明。定位证明不称为模型判断、市场事实或已核实交易。
- 假设、未知与反例的 check 嵌在本条笔记，包含 judgment、reason_code、quote_ids。机会问题和结论各有自己的 problem_check/conclusion_check；应用按对象位置生成内部 target，不要求模型重复目标编号或原文。
- 所有引用选择本轮原文目录的 Q 编号，应用确定性展开同一编号对应的正文和资料编号。未知编号、多余 claim/refs/check/anchors、重复编号、非 insufficient 却无依据、角色越权、重复分歧角色及原文失配仍严格拒绝。
- 新解析器只识别显式新格式；旧 claim-anchors/1 和 source-quote/1 的旧失败仍走原严格解析，不修补历史结果或赋予其成功状态。
- 内部保存结构不变，仍经过统一结构、引用、原文定位、目标覆盖检查。协议 evidence-review/7，当前生成 Schema 名称 review_v8_*。
- 独立反证首轮仍无前序输出或记忆；协调读取三个角色的有界摘要。预算、版本、幂等、lease、迟到结果与机会草稿确认边界保持。

第一次新格式复测在需求请求处得到 PROVIDER_CONFIG_ERROR，无用量回执、无接受的角色输出。随后检查发现新格式含官方不支持的 uniqueItems。已移除去重关键字，重复检查仍由应用严格执行，并增加发送前 Schema 兼容检查与固定词汇的错误诊断。

同类排查还移除了可选结论复核 Schema 中的 contains；请求仍受目标数、可用目标、主张原引用和原文片段约束，重复/遗漏目标由原 locateAudit 强制拒绝。未实际调用第二轮模型进行此变更验收。

官方兼容性依据（2026-10-15 检查）：https://www.alibabacloud.com/help/zh/model-studio/qwen-structured-output 。strict 模式不支持 uniqueItems、contains 等；不支持的字段提交会返回 400。本次不移除输出词元上限，不切换模型、不自动重试。

第三轮（claim-selections/1）的需求、商业与首轮反证均通过；协调在 `data.proposal.conclusion_check.reason:too_big` 停止。四次已用完，后续不追加真实请求。最后将检查说明改为新显式格式 claim-selections/2 的受控 reason_code，按判断类型限定枚举并映射到有界中文说明。来源、分析正文、反例与未知保留；不截断或接受旧超长输出。旧 claim-selections/1 解析保留严格的原长度检查。
