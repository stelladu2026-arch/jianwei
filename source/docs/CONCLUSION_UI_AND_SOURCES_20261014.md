## 结论界面

机会卡、完整执行草稿和阶段成果使用同一结论摘要：当前建议 → 下一步行动 → 反证与待验证项 → 可展开原文。完整研究记录和角色细节默认折叠，完成执行后先显示结论。

标签区分阶段判断、研究草稿、人工确认、历史输入和虚构演示。人工确认只表示确认该判断，不表示市场验证已经执行。尚无汇总时显示已接受阶段分析数量，不能从失败或空资料补写机会判断。自动草稿的确认提醒不再误触发“历史判断”。

完整执行的摘要重新校验保存的输入和输出，只展示通过原输入核查的结果；不会拿当前资料替代历史输入。已失效机会卡不借用当前正文证明旧判断。外来文本由 React 转义，不执行 HTML。

## 模型输出契约

- 查询工具只需 query，读取 HN 条目只需 id；未知字段、缺少必要参数或错误类型继续拒绝。旧合法 query/id 对象保持兼容。
- 独立固定原文分析禁止工具请求；一键 HN 单角色仍支持原有有界工具循环。
- 事实生成使用明确的 `fact_format=source-quote/1`。新 fact note 只有 kind/quote_id；Q 编号对应本轮固定原文的连续片段，由应用生成原文陈述及引用。
- 四角色 fact check 只填 target/supports/reason，应用按同一 Q 编号生成原文锚点；其他主张仍逐条填写引用与核查。
- 有可选原文时提供方 Schema 必填 fact_format，单角色生成最多 2 条 notes 与 2 条模型 citations，给新增最多 2 条确定性引用留出空间。内部原有 4 条引用上限保持。
- 新编号格式若带 claim/refs、未知编号、外来标记、重复核查、冲突锚点或超出新 wire 的容量，直接拒绝；不丢弃、覆盖或宽松修补。
- 旧自由文本 fact 和旧错误引用原样接受旧严格校验；不会修复历史被拒输出。
- 当前四角色协议 `evidence-review/5`，生成 Schema 名称 `review_v6_*`。原文陈述可定位并不证明来源、市场、因果关系或实际付款。

## 中文公开来源

新增 V2EX 节点公开 JSON Feed：`programmer`（程序员）、`create`（分享创造）、`qna`（问与答）。按官方节点页的订阅入口读取固定 `https://www.v2ex.com/feed/<node>.json`，不使用账号或 API Token。

操作者选择节点后，从公开订阅最多检查 50 条条目、保存 6 篇有正文的主题；不按关键词搜索全站，不翻页、不读评论、不取外链。发布时间必须有效且满足范围，空正文、重复、外站地址或异常日期不采纳。作者标识按 V2EX 命名空间散列；同作者/线程仍不能当独立客户。单轮 1 次来源请求、最多 1 次模型请求，不补搜、不发 HN 工具。

固定源、12 秒超时、512KB 响应限制、手动跳转检查；403、429、格式错、超大响应及网络失败均有安全中文指引，不重试或切换来源。未取得正文时保留阶段报告、停止分析，不把“未取得资料”写成“没有需求”。
