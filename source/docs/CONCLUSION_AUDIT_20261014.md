# 2026-10-14：可选结论反证复核

## 新增行为

四角色研究完整完成后，在“一键研究”下方显示“结论反证复核（可选第二轮）”。先明确确认免费保护和独立一次预算，创建本地检查点；检查全部待核查主张后，再执行一次模型请求。刷新页面不会自动执行或重放请求。

首轮独立反证仍只看冻结原文，不读前序结果和记忆。第二轮使用 verifier 角色，读取需求、商业、首轮反证及协调角色的全部笔记，以及协调的问题与结论。最多 10 项，完整文本不截断；超过整体 24,000 字符上限时，在请求前拒绝，不花费模型次数。这里复核的是笔记和 proposal.problem/conclusion，不声称覆盖 proposal 中的计划、替代、未知项或分歧解释等全部文字。

## 预算、来源与状态

- 原四角色上限仍为 4 次，第二轮单独上限 1 次；开启两轮后总分析请求最多 5 次。额外这一请求必须显式确认，不能把它藏在原轮预算中。
- 第二轮只复用原冻结资料，不检索、采集或调用工具；不加载解释性记忆。公开原文不构成实际付费核实。
- 每个 target 恰好一次。支持或部分支持的所有引文必须属于该主张原来的 refs；矛盾判断可引用其他冻结资料，保留反证机会。引文都须在对应 evidence_id 原文连续定位。无引文只允许证据不足。
- Provider Schema 逐目标约束判断、资料编号和可选原文片段；应用仍独立验证覆盖、重复、未知编号和逐字定位。没有修补历史拒绝结果或放宽首轮验证。
- 一个完成的四角色 workflow 只能创建一个复核记录；失败/取消后不能重置或追加请求。需要再次生成时，先明确新研究预算，以当前输入完成新的四角色流程；旧复核随研究记录归档。历史保留沿用当前项目的最近两轮限制，不是无限审计仓库。
- 请求前 CAS 保存一次预算预留与 75 秒 lease；模型超时仍是 45 秒。源指纹绑定冻结输入和全部前序角色输出；请求前/写入前验证。并发编辑、取消、暂停、归档或过期使迟到输出无法写入。未取得回执的用量保持未知。
- 正常失败保留安全回执、用量和字段路径，不存被拒的原始输出；取消/编辑后不覆盖新状态，也不猜测用量。
- 原研究草稿、自动待确认机会卡、人工对照和记忆不会被复核自动更新。复核支持度是待人工核查的模型判断，纠正通过既有人工反思入口记录。

## 界面操作

显示待核查主张、逐项结果、原文定位按钮、用量和失败字段。提供刷新、保留记录并结束复核、恢复过期检查点及人工反思入口。复核进行中阻止新研究/独立执行替换检查点。恢复过期只结束未知请求并保留已用预算，不重试模型。

旧项目 JSON 没有 conclusionAudit 时按未开启处理，无数据库迁移。新记录存于 workflow.conclusionAudit，项目导出和最近研究历史保留该字段。
