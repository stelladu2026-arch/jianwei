# 产品范围误排除修复 · 2026-10-30

## 原因

旧 sourceFit 将排除项字段里出现的全部受支持产品词视为排除对象。用户按给定项目范围填写“只研究 n8n，排除其他产品”等混合文字时，n8n 也会被排除，导致有原文却无法进入分析。26 条均被标同一排除原因与此代码缺陷一致；未读取用户线上项目或改写其数据。

## 修复与边界

- 按分句及有限限定表达识别产品排除。只研究/仅限、非 X 产品、除 X 以外等表达中的 X 不再自动当作排除对象。
- 裸列举排除项与明确排除仍有效；同一产品被明确排除时不以标题优先强行放行。
- 开发任务、界面副本及其他仓库规则保持有效；修复不是将所有原文认定为需求证据。
- 来源策略升级 topic-sources/9。旧轮用量、记录和项目范围不修改，不自动重新采集或调用模型。
- 新页面动态重算当前原文资格。若出现合格正文，用户可点“直接分析已有资料”创建新轮，跳过规划采集；旧轮仍保留结束状态。

## 离线验证

正反例覆盖：只研究 X、排除非 X、X 以外、明确排除 X、多产品裸列表、排除其他指定产品、开发任务仍拒绝、已有资料读路径不修改原文。完整 API 套件、类型与构建检查按本轮记录核对；真实模型调用为 0，未把用户的26条资料逐条核实为有效需求。

## 验收

优先使用原 n8n 项目：打开新预览，刷新，检查“可分析正文”是否恢复；展开剩余暂缓原因。仅在有合格正文时由用户显式点击“直接分析已有资料”，不用重新采集，也无需重新导入相同26条。
