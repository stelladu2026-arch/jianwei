# Harness 流程与界面验收指南

适用：见微 `research-harness/1`，以2026-10-28源码核对。它是验收方案，不是已通过的报告。

## 验什么

Harness 应能保持研究状态、复用已经确认的外部操作结果、阻止结果未知时自动重发，并在原预算和权限边界内恢复或后台接续。检查点计数增长、页面漂亮、生成一份报告都不能单独证明这些能力。

当前已接入 SDK、SQL 检查点/操作日志、恢复、后台推进及界面入口。隔离模型和数据库回归已通过；仓库最后真实联调仍为失败记录，修复后的真实完整链路未认证。本次仅整理方案，不调用真实模型。

## 入口与资料

1. 从项目总览新建验收专用研究，使用已获授权的真实资料或公开原文，确认研究范围。
2. 进入“一键研究”。固定演示是虚构回放；旧研究也可能继续使用旧执行器，不能用来验收新的 Harness。
3. 重点查看“研究检查点”“执行保障”“来源边界与执行记录”及最终机会草稿。
4. 工程故障试验使用脚本里的独立虚构线程，不写入真实项目。网页产品链路使用单独验收项目。

## 操作与通过标准

| 场景 | 怎么操作 | 界面应显示 | 工程/数据通过标准 |
|---|---|---|---|
| 启动及可观察性 | 确认范围后开始研究，展开执行记录 | 阶段、状态、当前阶段/整轮请求用量和已有成果有对应反馈；执行保障可读取 | 新研究带 Harness 版本；有对应线程、输入快照、操作回执和持久化检查点；页面计数来自实际记录 |
| 刷新与重新进入 | 记录当前阶段/用量，刷新或返回项目后重新进入 | 原研究仍可见，已完成资料与成果不丢；不因刷新自动新建一轮 | 项目/轮次保持，预算不清零；刷新仅读取状态，不重发已完成操作。若原请求仍在执行，等待结果或租约，不并发重跑 |
| 后台推进 | 在符合条件的等待继续状态，点击“继续后台推进”，关闭页面后重新进入 | 后台状态可读，完成时有成果；需要处理时有明确提示 | 有效数据库租约只允许一个后台执行者；使用原轮次和预算。若平台终止或接力未确认，提示手动继续，不假装无限常驻 |
| 暂停、结束与重复提交 | 在可操作时暂停/结束，或快速重复触发同一操作 | 状态与按钮一致，下一阶段停止推进；已有成果保留 | 不并发创建重复执行或重复保存；在途请求不能被当作退款或未消耗，已记录用量不回退 |
| 阶段内恢复 | 在独立工程线程里，于模型结果已写入回执、检查点写入失败时受控注入故障；再检查网页恢复入口 | 只有输入、版本、租约、错误类别均满足条件才出现“从已确认检查点恢复”；否则说明原因 | 恢复复用相同线程、原始输入和已确认回执；相同已完成调用不再发；后续新调用仍计入原预算。完成后再次回放，新增模型调用为0 |
| 结果不明或预算到顶 | 工程隔离测试注入未知结果/额度边界；网页核对对应状态 | 结果待确认的计数或明确停止原因；不能继续时不提供误导性的恢复入口 | 结果未知不自动重发；失败也计预算；不自动换模型、换轮次、换验收编号或增加额度 |
| 输入改变 | 独立验收项目暂停后修改范围/证据，返回旧研究 | 旧研究显示“依据已改变”等状态，保留旧成果并指向核对输入 | 旧检查点不能复用于不同输入；不能用改范围来清空旧轮消耗 |
| 完成与人工决策 | 正常完成后打开机会草稿，点引用查看原文，再人工复核保存 | 草稿与已确认机会有区分，原文可定位；重复进入/保存不生成重复卡 | 校验和保存不伪装成新增模型请求；引用属于对应输入；草稿成功不等于需求/付费已验证 |

恢复按钮不是常驻的。正常完成、结果不明、输入改变、尚有执行租约、模型/业务校验未通过，都可能不允许线程恢复；缺少按钮本身不能直接判定故障。

## 分阶段执行，先工程、后产品

| 阶段 | 配置与上限 | 通过后才继续 |
|---|---|---|
| A：真实工具循环与恢复 | 独立虚构工程线程，最多2次模型生成；新验收编号绑定新提交，付费预算0；失败即停 | 真正观察到工具执行、已确认结果后的故障恢复成功、完成回放新增0次。未请求工具不能冒充通过 |
| B：网页单角色完整链路 | 关闭“根据缺口最多补搜一轮”；界面整轮最多4次，每阶段最多2次，失败不自动重试 | 新建→确认范围→规划/采集→分析→校验/草稿保存，刷新与后台状态对应 |
| C：四角色复核 | 同一批已有原文，不重新采集；正常通常4次，应用硬上限8次，每阶段最多2次 | 需求/商业/独立反证/协调汇总各自留记录，独立反证首轮盲核查有效，引用/未知项保留 |
| D：独立结论反证复核 | 最多2次模型请求，失败计入，不采集新资料 | 主张覆盖、对应引文与反证可核查，不自动改写已确认机会或记忆 |

这些是各阶段的上限说明，不代表本次已获得或已使用全部额度。先批准并运行A，成功后再分别安排B/C/D；历史失败编号已封存，不能沿用或自动换号重发。付费预算0也不等于已核实账单金额为0，仍需核对上游用量。

## 验收记录最少字段

项目/轮次、提交版本、操作时间、前后阶段和状态、模型尝试次数、检查点数、已确认操作数、结果未知操作数、后台状态、安全请求编号及词元回执。没有回执的请求按未知记录，不按0计算。可保存不含资料正文与凭据的界面截图；后台报告只给摘要，不公开原始数据库检查点。

界面验收与工程验收都满足，才能说明 Harness 完整通过。当前独立分支 `harness/verification-20261028` 用于这部分工作，视觉版本单独保留。
