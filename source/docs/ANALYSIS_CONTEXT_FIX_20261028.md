# 分析阶段最终输入超限修复

用户 Flash 验收：规划与采集完成，归纳阶段 CONTEXT_LIMIT；已有2次模型请求及回执不重置。

定位：buildTask 先将基础输入控制在16000字符内，analysisTask 随后追加范围、来源说明、分析规则和检索说明，最终复检可能失败。该准备错误在路由预留模型次数前保存为 local/preparation，不是提供商上下文窗口报错。

修复：buildTask 可在预算检查前应用任务专用字段；analysisTask 将全部扩展字段提前组装，然后由原有确定性资料省略策略控制最终载荷。引用依赖保护、资料顺序、原文档案、输入快照与省略记录保留。仍无法满足预算时继续拒绝，不提高上限或自动请求。

回归：增加长研究范围及14条长资料场景，断言最终<=16000、快照一致、省略记录存在、原文未修改和请求计数未变。默认完整离线 API 回归及生产构建含类型检查。没有实际模型调用。

部署后由用户手动准备重试当前阶段，沿用旧预算；不重新采集、不重置历史次数。若本阶段实际存在其他错误须按新回执分析，不能保证语义结果。
