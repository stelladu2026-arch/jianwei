# 见微 · 产品机会研究 Agent

**在开始开发之前，把一个产品想法拆成可追溯的证据、反证和下一步验证行动。**

见微面向独立开发者、小型软件团队和产品经理，辅助回答：谁遇到了什么问题，现有方案是否足够，还有哪些关键证据没有找到？

当前为早期试用准备版本。可以先阅读案例，无需部署或填写模型密钥；模型研究结果需要人工复核。

## 它怎样帮助你

例如，你想开发一个“Dify 知识库应用发布前的引用自检工具”。见微帮助你整理公开问题和官方资料，区分故障报告与功能扩展请求，检查已有替代方案，再列出应该访谈的人、要观察的行为和继续投入的条件。

结果可能是“继续小规模验证”“补充关键证据”或“暂缓”。公开讨论、引用数量和模型评分都不能直接证明用户愿意付费。

## 当前能力

- **明确问题**：记录目标人群、场景、地域、时间范围及本次要支持的决定。
- **获取资料**：支持公开来源采集和手动导入；渠道是否执行取决于配置、主题与预算。
- **整理证据**：保留来源、原文片段和线程，区分原文与摘要，避免把同一讨论中的多条回复当作多个客户。
- **研究与反证**：单角色研究可进行受限工具调用；可进一步进行需求、商业、独立反证和协调复核，多角色收益尚未经过真实对照证明。
- **执行保障（Harness）**：保存检查点和操作回执，支持有边界的恢复与后台推进，保留失败和未知结果。
- **验证与导出**：生成待人工确认的机会草稿，记录验证计划和实际结果，导出 Markdown 或项目 JSON。

### 来源覆盖

| 来源类型 | 当前范围与限制 |
| --- | --- |
| 用户反馈线索 | GitHub Issues；配置后可用的 GitHub Discussions；有限社区主题与评论。讨论者不自动等于目标客户 |
| 官方能力核对 | 已接入的固定官方文档和有限版本记录，不能保证覆盖完整修复历史 |
| 通用发现 | Hacker News、中文维基百科、部分中文资讯与统计来源；Tavily、博查需要各自服务端配置 |
| 自有材料 | 粘贴、文件和受支持链接导入；使用者自行核对授权、来源及完整语境 |

新增渠道的代码接入不代表真实召回已验证；摘要不能冒充原文。具体配置见[上手说明](docs/open-source/QUICKSTART.md)，近期策略见[渠道更新](source/docs/ADDITIONAL_CHANNELS_20261029.md)及[来源预算分配](source/docs/P1_P2_ALLOCATION_AND_LAUNCH_20261029.md)。

## 已有证据与限制

- 已有真实单角色研究草稿；[公开案例](docs/open-source/CASE_DIFY_CITATIONS.md)展示了一次已有研究的摘要，而非本版本的全链路验收。
- 检查点、回执、恢复与后台推进已有实现和离线验证；新版本真实完整链路及故障恢复仍需按发布条件验收。
- 原文可定位不等于原文支持结论；没有经过校准的市场成功率，也没有已验证的付费转化率。
- 当前工作空间没有完整的多人资源隔离。开源部署与向多人开放在线服务是两项不同工作。
- 当前模型与地址仍固定在源码配置中，尚未提供通用模型切换设置。
- 尚未添加项目级开源许可证，本分支是发布材料准备稿。

## 项目结构

```text
source/                  应用源码、接口、编排、测试与历史工程记录
docs/open-source/        面向首次访问者的上手、案例与试用材料
START_HERE.md            历史 Cursor 交接入口
CURRENT_STATE.md         历史状态与增量记录，注意日期
```

当前 Node 部署路径使用 React、TypeScript、Next.js 和 Turso；原 Sites / Cloudflare 构建路径保留。研究执行包含 Deep Agents / LangGraph 相关组件，详见[执行保障现状](source/docs/HARNESS_STATUS_20261028.md)。

## 反馈

可以通过仓库 Issue 提交经过脱敏的使用反馈，说明你的研究问题、卡住的位置，以及哪条结论缺少支持。不要在公开 Issue 中提交客户原文、密钥或私人部署信息。

这版最想验证的是：**相比直接使用通用 AI，见微是否让你更快找到有用证据，并更清楚地决定下一步。**
