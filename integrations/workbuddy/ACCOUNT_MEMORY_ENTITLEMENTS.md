# 账号、记忆与免费/付费边界 · 2026-11-06

> 已确认首发选择：专家免费安装，模型使用用户自己的WorkBuddy额度。本版不单独注册、不建自有会员或付款门槛、不接作者模型服务；以下收费和后台能力保留为未来设计，不是当前免费版的上线前置条件。

用户新增要求：公开使用时需要明确账号体系、账户记忆和免费/付费功能区分。以下设计与当前实现严格分开，不能把平台能力当成自有后端已经具备的能力。

## 两种入口
| 能力 | 原生专家首发 | 网页/连接器后端完整版 |
| --- | --- | --- |
| 进入产品 | 用户在WorkBuddy登录并使用专家；专家不收集密码 | 自有经验证会话；平台OAuth仅在正式文档和权限已核对后接入 |
| 项目权限 | 不连接作者共享数据；仅本次授权文件与会话 | 每项查询/写入按服务器会话user_id及project_id授权 |
| 记忆 | 本次会话及用户主动提供的阶段文件；不承诺账户长期记忆 | 账户偏好、项目事实/纠正、运行上下文分开存储 |
| 付费 | 平台按专家/技能资产控制购买权限；免费/专业资产分开 | 后端权益、用量账本与支付状态；不能相信客户端plan |
| 收费后的云端文件 | 必须实测可用工具、文件持久性和下载，不假定本地脚本可运行 | 服务端任务与导出存储均校验用户权限 |

- https://open.workbuddy.cn/docs/buddy-app （平台记忆工程不等于本项目数据库已按账号隔离）

## 已核对的账户接入路径

官方 Open API：https://open.workbuddy.cn/docs/openapi ，2026-11-06核对。
OAuth2.1授权需要先有已创建的第三方应用（例如Buddy应用）及clientId/clientSecret；单独上传专家包不会自动给专家后端传可信用户身份。
授权码由服务端交换，响应含open_id。后端可按(provider, client_id, open_id)建立外部身份映射，再签发受控会话；不能把昵称、客户端自报open_id或本地目录名当用户身份。
必须校验一次性state、精确回调地址、实际授予scope、token时效和撤权；应用密钥仅保留服务端。上线前按平台实际支持核对完整OAuth2.1流程及客户端要求，不自行补造协议字段。
以上接口可用于获得授权身份，不证明平台已开放购买订单、订阅状态或自定义长期记忆读写接口。不可将资产购买和自有服务套餐自动绑定。

## 后台实施验收条件（尚未实现）
1. 认证：成熟认证库；注册/登录/退出/会话过期/账户删除。敏感API验证真实会话；cookie存在性只做导航提示。Cookie安全属性、同源与CSRF防护、登录限流。不得自写密码加密或把平台传来的user_id直接视为已登录。
2. 隔离：用户、会话、项目归属、资料、报告、记忆、任务、导出、用量均有owner关系；列表和单条读写都带owner条件，不能先读全表再前端过滤。不存在和无权访问按统一策略处理。
3. 迁移：旧单用户数据保持原状；明确验证拥有者后一次迁移，不默认分配给第一个注册用户或全站用户。上线前演练回滚和备份。
4. 记忆：分账户偏好、项目知识、运行上下文；有来源、范围、版本、确认状态、更新时间和有效期。用户可查看/纠正/删除/关闭；模型推测存候选，不能自动升级事实。账户A的记忆不得检索到B；过期和撤回的记忆不得进入新上下文。
5. 权益：plan、entitlement、有效期、用量reservation/settlement。并发下原子预占，幂等结算；超时按未知成本保留记录，不能自动退回当成零调用。免费额度耗尽前停止，不能任务结束后才检查。
6. 支付：只有已验证签名的幂等支付/退款/到期事件更新权益；前端“支付成功”、用户自述已买和跳转参数都不能开通。WorkBuddy专家购买记录如无官方可验证API，就不自动映射为网站套餐，也不向用户出售尚未接通的权益。
7. 到期：关闭新增付费任务，按说明保留数据读取/导出/删除；运行中任务遵循预先定义策略，不暗扣费。退款与撤销授权可回收后端权益。
8. 必测：未登录拒绝；A不能列出/猜ID读写B；伪造plan无效；并发额度不可超扣/超用；重复支付事件不重复加额；退款与到期撤权；删除记忆后新运行不召回；删账户后关联数据按政策处理。

## 当前状态
当前原生专家候选仅实现研究指令、本地引文检查与打包，不实现上述后台账号、账户记忆或支付系统。现网页仍是所有者共享验收环境；不能据此作为公开多人收费网站。
完整账户版需要独立迁移分支、数据库与认证配置、服务端路由改造、真实双账号和支付沙箱验收。无需先购买服务或向对话粘贴密钥。
